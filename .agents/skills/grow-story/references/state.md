# 最小项目记录

维护 current.json，其中 version、events、characters、world、dependencies、foreshadowing 属于同一快照。另存历史快照与简短的尝试记录。先读 current.json，再按需读原文；定期分批复核遗漏。

所有集合条目均有稳定 id。事件字段：id、arc、text。用稳定事件编号定位，顺序由 events 列表决定；移动不换号。同一客观事件的其他剧情表达用 event_refs 引用权威事件；回忆/传言注明视角、时间和认知性质，不复制为独立事实。拆分事件记录旧到新编号映射；删除不复用编号。
人物字段：id、name、facts。每条 facts 写 text、evidence（事件 id 与精确 quote）、kind（explicit 或 inference）；推测不能默认为事实。事实涵盖经历、目标、关系、已知信息和变化，不把性格标签写死。
世界记录同样用 text、evidence、kind，注明时间/适用范围；必要核心事实直接加载。依赖记录说明前提事件、结果事件及必要条件/推动因素，给出依据；先后发生不等于因果。伏笔记录埋设、兑现与状态；无伏笔不必造条目。

引用必须在当前引用事件原文中匹配。事件改动后重验所有引用；旧事实失效时明确替代，历史仍保留。候选依赖未定世界机制时先给出兼容补充并回查旧事件；不暗换尺度规则。

检索可组合事件编号、人物编号、关键词、向量和关系遍历；编号仅负责准确定位，不保证召回。没有实现向量索引时用全文/关键词并说明限制。源剧情优先于派生摘要；冲突时核对上下文，不直接用新句覆盖旧事实。

写入顺序：构思并审核完整的故事改动→仅输出已采用事件及对应记忆的局部变更包→程序重建完整候选并核对 id、原句、版本与依赖→保留旧快照→原子替换发布 current.json。具体协议与脚本见 delta.md。不要先更新当前人物卡再审核故事。程序校验引用只能证明结构一致，不能证明语义或故事质量。
