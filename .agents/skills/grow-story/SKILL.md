# 剧情生长

以完整故事替换完整故事；用新事件强化薄弱连接、人物选择与关系，而不以增加字数为目标。直接交代必要情绪和动机，保留简洁叙事。每个交付版本有起因、过程和结果；允许结局有遗憾，不将待定原因或必要前提欠账当作悬念。

## 一轮工作
1. 读取当前有效故事、人物及相关世界事实，核对事件原文。自行选择有价值的发展位置；优先从已有角色的经历、利益和关系寻找机会，同时允许必要的新人物。
2. 自主探索候选。对有意义的不同方向给足发展机会再判断，可在预算内重试。不要固定候选数量、字数、步骤数或要求最短补丁。允许跨剧情弧回改早年事件；不要默认人物早已预知未来。
3. 按 [continuity.md](references/continuity.md) 审核候选与整篇的联系：人物经历和表达是否连续，共同事件在不同剧情中是否一致，改动是否影响其他剧情弧及主线；记录证据与未覆盖范围。检查因果、人物认知、时间、尺度和利益关系。针对候选新使用的事实查找旧原文，不仅查摘要。区分故事事实、人物说法和推测；查不到不等于不存在。让相关人物有合理替代选择，检查为何未采用，但不以最短路径抹平曲折。
4. 修正或撤回尚有已知因果缺口的候选；保留当前完整版本，直到有更好的完整版本。没有收益可不修改。用完尝试预算就选已检查、能成立的最佳版本，诚实报告剩余不确定性；不要承诺绝无漏洞。
5. 通过检查后，将故事与对应记忆准备为同一新版本，验证来源引用和版本一致后一次发布。失败保留上一版。仅从采用后的故事更新人物、设定、关系、事件依赖和伏笔；草稿不得污染正式记忆。采用以后仍可明确回改，不代表永久冻结。

仅在需要创建或维护项目记录时读取 [state.md](references/state.md)。提交修改时读取 [delta.md](references/delta.md)，只生成局部变更包，由 scripts/apply_patch.py 合并，勿让模型重写整份状态。没有文件工具时明确为会话演示，不声称保存或运行了检索。

## 汇报
简要说明采用的改动、检查发现、同步记录和实际保存状态。用户开发工具时，以机制表现与失败证据为主；不反复询问下一段写哪里，不把一次好故事当作稳定性证明。不要展示私有思考过程；保留可核查的候选摘要与修改依据。

## 拆书
按需从完整剧情反向压缩到种子，观察删除/恢复事件造成的选择、因果和关系变化。把方法连同来源、适用边界和反例作为候选参考，用新故事验证后再纳入；不训练模型，不把某个原作桥段变成通用强制套路。
